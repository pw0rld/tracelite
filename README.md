# TraceLite

面向 **Mac + Chrome + Shadowrocket（小火箭）** 的本地 Manifest V3 扩展。安装后通过 Chrome 原生设置减少追踪和 WebRTC 绕过代理的风险；系统 DNS、VPN 路由和浏览器指纹仍需分别处理。

**v0.9.1 调整为暖白底、白色卡片与单一低饱和绿强调的轻量界面，去掉卡通角色、粉彩分区与俏皮文案。** 只提供 400×600 小弹窗；基础设置、地区编辑和权限说明都收在弹窗内的小抽屉，不打开独立网站或大管理页。追踪拦截、链接清理、缓存／数据分离清理及暂停恢复继续保留，后台功能与权限保持原有范围。

## 安装与恢复

本机可直接加载下方已有目录，无需使用 ZIP。下载的 `TraceLite-v0.9.1.zip` 是纯扩展包，应先解压，再选择**直接包含 `manifest.json` 的文件夹**；不要将 ZIP 文件交给“加载已解压的扩展程序”。`-source.zip` 是源码与验证材料，不是安装目录。现有安装只需重新加载原扩展；目录保留以维持原扩展 ID 与保存的设置。

1. 在 Chrome 地址栏打开 `chrome://extensions`，开启右上角“开发者模式”。
2. 点击“加载已解压的扩展程序”，选择克隆或解压后项目内的 `extension` 文件夹。
3. 从工具栏打开扩展，检查每项的实际状态。安装后默认启用下表设置；被企业策略或其他扩展控制的项目会单独提示。
4. 如果使用无痕窗口，在扩展详情里检查是否需要开启“在无痕模式下启用”。不要假定普通窗口测试结果自动适用于无痕窗口。

macOS 选择文件夹时可按 `⌘⇧G`，输入你本地项目中 `extension` 文件夹的完整路径，再回车选择该目录。

暂停保护会清除**本扩展自己的设置覆盖**，恢复由 Chrome、用户、策略和其他扩展决定的值，而非强制把项目改为开启。恢复保护会重新应用所选设置。禁用或卸载扩展也会撤销其 ChromeSetting 覆盖。[设置生命周期](https://developer.chrome.com/docs/extensions/reference/api/types)

## 默认改变什么

| 设置 | 默认行为 | 局限 |
| --- | --- | --- |
| WebRTC | `disable_non_proxied_udp` | 限制未经过代理的 UDP；不是关闭 WebRTC，也不能保证没有公网地址候选 |
| 网络预测 | 关闭 | 减少 Chrome 预测、预加载；网页主动发起的 DNS 预取和预连接仍可能发生 |
| 第三方 Cookie | 关闭 | 站点授权、Storage Access API 等仍可能构成例外 |
| 链接审计 | 关闭 | 阻止 `<a ping>` 审计请求，不阻止所有点击统计 |
| Topics | 关闭 | API 不可用时显示不支持 |
| Protected Audience / Fledge | 关闭 | API 不可用时显示不支持 |
| 广告衡量 | 关闭 | API 不可用时显示不支持 |

每项读取控制权、设置后再次读取核对；“不支持”“被其他扩展控制”不代表已受到保护。广告相关 API 只允许扩展关闭，因此撤销时使用 `clear()`，不调用 `set(true)`。[Chrome 隐私 API](https://developer.chrome.com/docs/extensions/reference/api/privacy)

基础保护通过 Chrome 原生设置工作，不改写页面 API，无遥测、远程代码。打开扩展时可只读核对当前页语言与时区；可选地区模式在获准网站运行本扩展随包的覆盖代码。不会伪造 UA、Canvas、WebGL、字体或 CPU 数量，也不接管代理。原生设置无法全面隐藏这些指纹；仅仅让检测页显示绿色不是本项目目标。

## 追踪保护与手动清理

### 请求保护

“拦截第三方追踪请求”和“谨慎清理链接参数”是两个独立开关，首次开启会按需申请 HTTP(S) 网站访问。已有地区授权时可复用，不会要求开启地区模式。新增功能默认关闭；不开启也不影响既有七项原生隐私设置。

- **追踪请求拦截**：随包提供原创、保守的 20 个基础追踪域名单，只阻断第三方子请求，不阻止用户直接打开该域名。不下载远程规则或代码；不是完整广告拦截名单，也不保证覆盖第一方或未知追踪。名单日期和范围见 `extension/tracking-rules.js`。
- **链接参数清理**：只处理 GET 主页面导航中的 11 个明确参数：`utm_source`、`utm_medium`、`utm_campaign`、`utm_term`、`utm_content`、`utm_id`、`fbclid`、`gclid`、`dclid`、`msclkid`、`ttclid`。允许保留并混用的普通查询键仅有 `q`、`page`、`id`、`v`、`t`；整个查询含其他未知、OAuth 或签名相关参数时跳过。参数名按明确的小写键匹配，不修改 POST、页面脚本读数或任意 token；无法保证任意业务签名链接都可安全改写。
- **域名例外**：当前域名及其子域可同时暂停这两项。“站点选项”内可设置；“设置 → 基础保护 → 追踪规则与域名例外”可移除。例外按域名生效，覆盖 HTTP/HTTPS 和不同端口，不承诺精确来源隔离；不改变地区设置或原生隐私设置。
- **暂停／恢复**：总开关暂停时移除本模块规则但保留两项选择和例外；恢复时仅恢复已选择项目。撤销网站访问后取消两项启用意图并清理，重新授权不会自动重开。清理失败显示“待清理”，不会显示完全暂停。请求规则使用独立 ID 范围，不删除地区语言头规则。

### 两种手动清理

| 按钮 | 删除范围 | 保留范围 |
| --- | --- | --- |
| 清本站缓存 | 当前来源的 HTTP 缓存，包括其中可能保存的 ETag 编号 | Cookie、LocalStorage、IndexedDB、CacheStorage、Service Worker |
| 清本站数据 | Cookie、LocalStorage、IndexedDB、CacheStorage、Service Worker、来源文件系统数据 | HTTP 缓存；浏览历史、下载记录、密码和表单数据 |

首次点击清理按钮才申请可选 `browsingData` 权限；授权后仍会显示目标来源和确认框。**清站点数据可能退出登录，删除离线／已安装网页应用数据；Cookie 会连带同一可注册主域及其子域。** HTTP 缓存和其他站点存储仍按精确来源过滤，不清全局或扩展数据。[Chrome 官方清理范围](https://developer.chrome.com/docs/extensions/reference/api/browsingData#specific-origins)

无痕窗口不提供清理，以免误删普通窗口。操作需短期、一次性确认令牌，导航变化、确认过期或重复提交会被拒绝。清理任务独立运行，关闭弹窗后可重新查看进度，不占暂停操作的设置队列；后台重启导致结果无法确认时显示“未知”，不自动重新执行。

清理可以在总开关暂停时手动使用；暂停不会取消已确认启动的删除，也无法恢复已删除的数据。不会自动刷新页面；仍打开的网页可能再次写回记录。清理不改变硬件指纹、网站服务器记录或已登录账号的关联。

v0.8.0 验证：197 项单测通过；Chrome 157 与 Brave（Chromium 157）临时配置验证请求阻断、链接清理、域名例外、暂停恢复、权限撤销及与地区语言规则共存。Chrome 157 的两站 HTTPS 测试验证缓存与数据分开、目标站与另一站隔离、关闭管理页后读取任务结果、暂停中手动清理。0.7.1 升级的启用／暂停／停止三态及保存组合均验证保留。测试全部使用自写回环页面、临时配置和预授权副本；首次原生权限弹窗、日常 Brave Shields 名单及外部真实追踪服务未作为通过标准。报告见 `verification/chrome-protection-smoke.json`、`verification/brave-protection-smoke.json`、`verification/chrome-cleanup-smoke.json` 和 `verification/chrome-upgrade-smoke.txt`。

## 原生与地区预设

**地区覆盖默认关闭；主动启用后用于获准的 HTTP(S) 网站。** 列表首项“保留浏览器原生”不覆盖时区、语言 API 或语言请求头，不申请地区功能的网站访问权限。它停止旧覆盖并保留该选择；已打开页面需刷新后才会恢复原生值。任何组合都不承诺降低指纹追踪。

升级会保留已保存组合和地区启用／停止状态；此前撤销权限或主动停止的地区模式不会重新开启，总开关已暂停时也会继续暂停。旧组合没有模式字段时，其时区与语言继续按覆盖处理，不会悄悄改变原有选择。升级自 v0.2 仍会保留预设并停止旧覆盖，需要你重新明确启用。

| 预设 | 时区 | 网页语言及默认区域格式 |
| --- | --- | --- |
| 保留浏览器原生 | 不覆盖 | 不覆盖 API 或 `Accept-Language` |
| 日本 · 日语 | `Asia/Tokyo` | `ja-JP, ja` |
| 新加坡 · 英语 | `Asia/Singapore` | `en-SG, en` |
| 美国洛杉矶 · 英语 | `America/Los_Angeles` | `en-US, en` |
| 美国纽约 · 英语 | `America/New_York` | `en-US, en` |

也可展开“自定义／另存组合”，保存最多 20 组。时区与语言分别提供“保留浏览器原生”选项：

| 自定义模式 | 页面时区 | 语言、默认区域格式及语言请求头 |
| --- | --- | --- |
| 两项原生 | 不覆盖 | 不覆盖 |
| 仅覆盖时区 | 使用指定 IANA 时区 | 保留原生 |
| 仅覆盖语言 | 保留原生 | 使用指定 BCP 47 格式与语言顺序 |
| 两项覆盖 | 使用指定 IANA 时区 | 使用指定 BCP 47 格式与语言顺序 |

勾选原生后，对应输入会禁用；保存和启用组合前不会改变网页。原生选项停止对应覆盖，刷新后生效，不修改 macOS 或 Chrome 界面设置。覆盖语言时，第一语言需与默认区域格式一致。美国时区会按日期处理夏令时，而非固定写成 UTC−8。页面级覆盖仍能被检测；减少覆盖不等于隐藏真实环境。

首次启用：

1. 更新文件后，在 `chrome://extensions` 找到本扩展并点击重新加载。
2. 打开普通网页。选择原生组合后点击“保持原生并刷新”，不会申请网站访问权限；选择包含覆盖的组合后点击“启用并刷新”，首次会请求 HTTP(S) 网站访问与标签页权限，拒绝不会影响基础隐私保护。已有的脚本执行、请求头规则 API 现为固定权限，以可靠初始化并在撤销网站访问后仍能清理；不需要“允许运行用户脚本”。
3. 所选组合用于新载入的 HTTP(S) 网页。已有页面需要刷新；点击主界面“地区与语言”或“设置 → 地区与语言”，在弹窗抽屉内查看读数、编辑组合、检查详细状态。
4. “停止地区模式”取消启用意图并清理未来注入与语言请求头规则，但不会替你刷新已有页面，以免丢失表单。可点击“刷新当前页”或确认后“刷新受影响页面”；需要刷新的数量会持续显示。
5. 总开关暂停会保存你此前主动启用的组合；恢复总开关时重新应用该组合。**检测到地区权限撤销时则取消启用意图**，权限恢复后只重试清理，不会自动开启地区模式，必须再次点击“启用并刷新”。

实现：先安装 `Accept-Language` 规则，再注册普通内容脚本。四组内置配置使用随包的固定 `MAIN document_start` 文件；后台随后只核对读数，不再半途修改同一文档。不匹配内置参数的自定义组合保留逐文档后台授权后覆盖，因此可能晚于网页首次读取。两项原生不安装覆盖脚本或语言规则。所有动态注册均不跨浏览器会话持久化；浏览器重启、升级或已有页面未获得前置入口时，应检查实际读数并手动刷新。注册与 Chrome 网站权限承载内置模式的授权，后台不再能在每次执行前同步确认内置预设。[内容脚本官方文档](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)、[脚本执行接口](https://developer.chrome.com/docs/extensions/reference/api/scripting)、[请求规则官方文档](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest)

暂停/撤销失败会分别保留“脚本待清理”“请求头待清理”，不显示成已完全关闭。恢复所需权限后可点“恢复权限并清理”，只清理旧规则，不会重新开启地区模式。要明确停止，使用扩展内“停止地区模式”；恢复网站访问权限不等于重新启用地区模式。

顶部 `!` 表示有设置或清理未完成；开启时 `↻` 表示旧页面需刷新，暂停时保留 `OFF` 并在标题和正文说明待刷新。基础保护的状态与地区功能分别展示；已保存地区不代表已启用。移除了旧版本暴露在页面全局的扩展标记，但这并不让页面补丁变得不可检测。

**边界：这是可检测的页面级兼容覆盖，不是完整防指纹。** 可访问的同源 iframe 和符合下方条件的经典 Blob Worker 会同步设置。HTTP、模块、共享及 Service Worker，跨源/opaque 框架、主页面授权前创建的上下文、未覆盖的访问路径和其他扩展的隔离环境仍可能保留原始读数。页面显式指定的时区/语言予以保留；宽松历史日期解析、`Number.prototype.toLocaleString` 等部分内建路径仍可能使用原设置。时区和语言一致不代表你成了该地区的匿名用户。

开发时实测 Chrome 157 拒绝普通扩展调用原生 `setTimezoneOverride` / `setLocaleOverride`，返回“only available to trusted clients”；因此最终版本不申请 `debugger` 权限，不声称实现内核级覆盖。

## 对敏感站点加强保护

可选的“阻止本站 JavaScript”针对当前 HTTP(S) 来源生效。启用后重新加载页面；登录、支付、验证码、视频和应用页面可能失效。解除后也需重新加载。它能阻断大量脚本探测，但请求头、IP、TLS/TCP 等仍然可见。[Chrome 内容设置](https://developer.chrome.com/docs/extensions/reference/api/contentSettings)

暂停扩展时会清除本扩展管理的 JavaScript 阻止规则；恢复保护时重新应用保存的规则。扩展只管理自己保存的名单。

缓存清理入口打开 Chrome 设置，由你选择范围。要删除 ETag 缓存编号，需要清“缓存的图片和文件”；要同时清其他标识，还要清“Cookie 和其他网站数据”。后者可能退出网站登录。扩展不自动删除浏览数据，也不全站禁用缓存。关闭检测页后再清理，避免打开的页面立即重新写入。

## 小火箭与 Chrome 配套设置

Shadowrocket 官方列出 Mac、IPv6 和 DoH/DoT/DoQ 支持，但公开说明不足以确认所有版本的开关名称、DNS 路由与断线行为。下面按目的配置，不照搬 Surge 或 Mihomo 的配置键。[官方 App Store 页面](https://apps.apple.com/us/app/shadowrocket/id932747118)

1. **使用小火箭的系统 VPN 连接。**在 macOS 系统设置的 VPN 页面确认连接已启用。隐私浏览期间，在小火箭中选择全局代理路由及固定节点；检查域名、IP、应用和局域网绕过规则。仅设置 HTTP 系统代理不能覆盖所有 UDP/DNS。
2. **让网站域名的 DNS 也经过代理。**选择可信的加密 DNS，并核对小火箭日志里 DNS 上游连接的出口。DoH 只保护传输，直连 DoH 仍向解析服务暴露真实出口；节点地址本身的引导解析也应单独考虑。
3. **Chrome 安全 DNS 二选一。**只有确认小火箭已完整接管系统 DNS 后，才关闭 Chrome“使用安全 DNS”，交给小火箭统一解析。另一条路径是在 `chrome://settings/security` 指定自定义 DoH 服务，例如 `https://cloudflare-dns.com/dns-query`，并确认该服务本身经代理；不要只选择可自动降级的模式。Google 说明自定义服务失败时不会回退未加密 DNS，但自动模式可能回退。两种方案都需实测，扩展无法替你配置系统 DNS。[Chrome 安全 DNS 说明](https://support.google.com/chrome/answer/10468685?co=GENIE.Platform%3DDesktop&hl=zh-Hans)、[DoH 端点](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/)
4. **UDP 不能直连兜底。**优先使用支持 UDP 的节点；如所用版本提供“不支持 UDP 时”的动作，应选拒绝而非直连。扩展的 WebRTC 限制可能使通话退回 TCP 或失败。不要为修复通话把整个浏览器切回直连。
5. **IPv6 一起处理。**要么验证 IPv6 经代理，要么在该 VPN 配置中明确阻断未受保护的 IPv6 并验证结果。关闭一个“IPv6 DNS”选项未必关闭 IPv6 出站；不必先永久禁用整个 Mac 的 IPv6。

若采用 Chrome 自定义 DoH，会绕过小火箭的部分 DNS / fake-IP 逻辑，按域名分流可能改变；因此先用全局代理验证。自定义 DoH 不等于零 DNS 暴露：解析器地址的引导查询、应用自己的 DNS 和系统请求仍取决于 VPN 路由。DNS 请求需要由某个解析服务处理，因此“解析器能看到查询”与“本地 ISP 意外看到查询”应分开判断。

不要为这些隐私设置开启 HTTPS 解密 / MITM 或安装根证书。无需一律关闭 QUIC；关键是 UDP 经代理或被拒绝，而不是失败后直连。小火箭的全局路由、按需连接或强制路由也不自动证明具备断线阻断。

保留 Chrome 自动更新、安全浏览和密码管理。可另建专用 Chrome 配置文件，减少扩展数量，并避免把工作账号与需要隔离的访问混用；配置文件隔离 Cookie，但不会自动改变硬件指纹。

## 安装后验证

- 查看扩展各项的实际状态，再分别测试普通、无痕窗口。

## v0.5.1 与公开检测项对照（历史）

依据 [who-are-you 的公开 app.js](https://github.com/yt1988/who-are-you/blob/main/src/app.js) 与 [infer.mjs](https://github.com/yt1988/who-are-you/blob/main/src/infer.mjs) 核对。公开 main 可能与线上部署不同；本地验证执行的是自写的同类检查，不下载或执行网站脚本。

| 检测位置 | 它怎样判断 | 本版处理与剩余范围 |
| --- | --- | --- |
| `lies()` | 用新 iframe 的 `Function.prototype.toString` 检查函数；检查多出的 `prototype`；getter 对伪造 receiver 应抛 TypeError | Date 方法、Date.parse 与语言 getter 用原函数为目标的 Proxy；保留函数元数据和属性标志，非法 receiver 交给原生接口处理。未改写 `Function.prototype.toString` |
| `locale()` / `tampered()` | 比较 Intl 时区偏移、Date 偏移、Date 字符串偏移；比较 HTTP 首选语言与 JS 语言 | 本地 Chrome 检查偏移一致；完整扩展回归确认语言请求头与页面一致 |
| `lies()` 的 frame 对比 | 同步新建空白 iframe，立即比较语言、时区等 | 仍有差异；异步的文档授权无法保证先于同步读取完成 |
| `workerNav()` / `fpbTraces()` | 新建 Worker，比较语言、时区、UA、平台 | Worker 未覆盖，仍能发现语言、时区与页面不同 |
| `tampered()` 的汇总 | 一项异常也可能触发综合警告 | 部分反射检查改善不保证综合结果变绿 |

另修正 Intl 实例与对外构造器的一致性、Date.parse 的字符串转换语义。地区切换仍保留且默认关闭；不新增权限，不改动 UA、绘图、音频或 Worker，不针对检测域名返回特例结果。更新后重新加载扩展并刷新旧页面，已有页面不会被静默重载。

## v0.6.0 同源 iframe 与部分 Blob Worker

- 读取可访问的同源 `contentWindow` / `contentDocument` 时，在返回前同步应用同一组合；常用 DOM 插入方法、新增子树观察和 load 回补覆盖更多路径。以 Document 身份去重，导航后的新文档能再次应用；不会尝试访问跨源或 opaque sandbox 的内容。子框架的语言数组使用子框架自己的 Array，避免制造新的 realm 差异。
- Worker 覆盖范围严格限定为：页面在覆盖启用后用当前 realm 的普通字符串数组构造、可以同步取得源码的 JavaScript Blob，再用其 URL 创建、未传入 options 的经典 Worker。用原生结构化克隆排除 Proxy 等不能可靠重建的输入。保留显式分号结束的指令序言（包括 `"use strict";`）、BOM、hashbang 和注释；有歧义的输入不改写。不使用 eval/importScripts，不放宽 CSP 或 Trusted Types；存在默认 Trusted Types policy 时透传。
- HTTP、module、Shared、Service Worker、带 options、未知 Blob、非字符串部分、无法确认指令序言等路径保持原有行为。捕获和资源跟踪都有数量限制，超限后透传。**包装后的 Worker 使用新的 Blob URL，`location.href` 会变化，仍可成为识别点。** 不保证涵盖全部 Worker 或所有 iframe 访问路径。
- 暂停、停止、切换组合或撤销地区权限时，先撤销文档授权，再通过已有隔离内容脚本发出仅用于停止传播的随机事件。已收到通知的旧页不再向新 iframe/Worker 传播旧设置。通知最多等待 1.2 秒；无法联系的页面仍需刷新。原页面已修改的 API、已运行的 Worker 不强行逆向恢复或终止，刷新提示继续保留。
- 前进/后退缓存保留的文档也保留对应钩子；浏览器恢复该文档时重新核对权限与配置代次，已暂停或过期的文档会收到停止通知。恢复校验仍为异步流程，不保证先于该页面所有脚本执行。
- 不新增权限，地区模式仍默认关闭。`npm run build` 将随包的源函数组合成可序列化入口 `page-context.js`；运行时不使用 eval 或 new Function。`npm test` 和打包都会先更新入口。

本地测试确认所覆盖的空白 iframe 和经典 Blob Worker 读数差异已消除，不等于真实检测网站全部通过，更不等于匿名或不可检测。
